## Where AI Assistance Was Used

### 1. Project Scaffold (Backend)

Claude generated the initial directory layout and the first version of the four core backend files:

- `main.py` — FastAPI server with CORS and the `/recommend` endpoint
- `graph.py` — LangGraph `StateGraph` with the decide / rag / web / both / generate nodes
- `rag.py` — FAISS vector store and Gemini embedding pipeline
- `web_tool.py` — `@tool`-decorated web search wrapper (Tavily + mock fallback)
- `games_data.py` — the 20-game curated corpus

We modified all of these afterwards (see "Modifications" below).

### 2. Frontend Visual Design

The initial React/Tailwind UI (the popular-games grid, mascot, hero section, response card with markdown rendering) was generated by **DeepSeek** based on a prompt we wrote ourselves describing:

- The agent's purpose and behavior
- The exact API contract (`POST /recommend`, `{route, answer}`)
- The Markdown format the backend returns
- The tone we wanted ("dark gaming aesthetic, neon green/cyan accents")

We then integrated the generated `App.jsx` into our Vite project and made several modifications (see below).

### 3. Debugging and Environment Issues

Claude helped us resolve:

- A `faiss-cpu` version-pinning conflict on Python 3.14 (Windows)
- A NumPy build error caused by Python 3.14 + missing GCC on Windows
- Switching from OpenAI to Google Gemini after our OpenAI account ran out of credits
- A `404 NOT_FOUND` error when an outdated Gemini embedding model name (`text-embedding-004`) was deprecated — Claude wrote a `list_models.py` helper script that calls Google's `list_models()` to discover the correct current model names
- Pylance "import could not be resolved" warnings caused by VS Code pointing at the wrong Python interpreter
- A `403 PERMISSION_DENIED — API key was reported as leaked` error after we accidentally exposed a key (we rotated the key)
- A 503 "model overloaded" handler that automatically falls back to a secondary Gemini model
- Gemini free-tier quota management (chose `gemini-2.0-flash` for its higher daily quota)

### 4. Architectural Decisions

We discussed routing strategy with Claude. Initially the `decide` node used only a hardcoded keyword list (`"latest"`, `"2026"`, etc.). After observing that queries like *"recommend something like Valorant"* were misrouted to the local DB, Claude proposed adding an LLM-based classifier as a second layer. We adopted this hybrid (keyword + LLM) approach because it is both predictable for demo and intelligent at the edges.

### 5. Documentation

The first drafts of `README.md` and this `AI_USAGE.md` were generated by Claude. We reviewed and edited both.

## Modifications We Made by Hand

After the AI-generated scaffold, we made the following changes ourselves:

- Switched LLM provider from OpenAI to **Google Gemini** (added `langchain-google-genai`, updated `rag.py` to use `GoogleGenerativeAIEmbeddings`, replaced `ChatOpenAI` with `ChatGoogleGenerativeAI`)
- Migrated the embedding model from the deprecated `text-embedding-004` to `gemini-embedding-001`
- Replaced `gemini-2.5-flash` with `gemini-2.0-flash` after hitting the lower daily quota of 2.5
- Replaced the original SVG-based `GameCover` component in `App.jsx` with one that loads real Steam CDN cover art for popular games
- Updated the `POPULAR` game list (titles, genres, image URLs) to reflect actual currently-popular games
- Added a `fallback_llm` mechanism with a try/except chain so the agent gracefully degrades when the primary model is overloaded
- Strengthened the routing prompt with explicit instructions about which game categories live in the local DB versus the web
- Added a `.gitignore` covering `.env`, `node_modules`, `venv`, and other local artifacts
- Tested every code path end-to-end (RAG-only queries, web-only queries, and queries that legitimately need both)
